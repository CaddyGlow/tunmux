## Findings fixed during validation

- Explicitly set launchd socket owner/group: `GroupName` alone left the socket in
  group `daemon`, preventing activation by the authorized login user.
- Validate Unix stream/listen behavior without requiring identical pathname spelling
  or relying on Darwin's observed `SO_ACCEPTCONN` result. Native descriptor tests
  cover a listener and reject a connected stream.
- Bound privileged socket/stdio exchanges and probe activation before effects; a
  crashing activation job previously left a connect holding the user operation lock.
- Use short, private per-user proxy control paths and nonblocking framed exchanges
  with total deadlines; native tests caught path length and fractional timeout issues.
- The first LAN plan expanded broad routes unnecessarily and exceeded the setup
  budget. Startup failed and rolled back; no tunnel or recovery journal remained.
  The replacement keeps physical connected-route precedence and omits only VPN
  routes that would override it. Native LAN opt-in startup and teardown passed in
  the 2026-10-20 suite rerun; physical LAN reachability remains an operator check.
- The administrator suite reached the SIGKILL recovery path on 2026-10-20.
  Network recovery succeeded, but identity-verified recovery left protected stale
  socket nodes, so the login user's occupancy check treated EACCES as a live owner.
  Recovery now removes both stopped endpoints before acknowledgment, under the
  identity-verified session lock. Connect preparation also uses privileged inspection
  and identity-checked recovery for orphaned endpoints after user-state removal.
  The socket cleanup regression preserves identity/lock receipts and unrelated
  endpoints. Native crash recovery passed in the 2026-10-20 suite rerun.
